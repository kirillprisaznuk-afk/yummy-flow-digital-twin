## Findings and resolutions

| Finding | Evidence / risk | Resolution |
| --- | --- | --- |
| Recurring throughput caused inconsistent break-even decisions | 9,000 minutes/month ÷ 7 minutes/order at €7 contribution should yield exactly €9,000. Version 1.0 produced €0.000000000000000000000002 surplus against €9,000 fixed costs, yet reported a capacity shortfall | Keep throughput and threshold ratios exact until Decimal output conversion; the regression now reports exactly zero profit and reachable break-even |
| Standalone economics could bypass capacity | Calling the old two-argument function with 700 served orders and zero riders produced €629,790 revenue | Remove the caller-supplied fulfilled-volume argument; `calculate_economics(assumptions)` derives capacity itself |
| Zero-cost break-even was contradictory | Zero demand and zero fixed costs could report current break-even as true but threshold reachability as false when contribution was nonpositive | Explicit zero-activity threshold and `zero_fixed_costs` reason; document that negative contribution still makes growth unprofitable |
| Model copying bypassed validation | Pydantic's original `model_copy(update={"gross_margin": 2})` accepted an invalid margin | Override copying to revalidate immutable scalar inputs; revalidate constructed models at calculation entry points |
| Partial replacement silently reset assumptions | A name-only or partial-assumptions `PUT` could replace saved business inputs with defaults | Require all assumption fields on replacement; failed replacement leaves the stored record unchanged |
| Incomplete stored JSON inherited live defaults | A missing saved field was silently supplied by the current assumption model | Require complete saved snapshots; invalid/missing assumptions return 409 |
| Version compatibility blocked retrieval as well as recalculation | The original version check prevented inspection of any incompatible record | Current model is 1.1; valid old input snapshots remain retrievable, but recalculation/replacement requires a matching version. Explicit creation of a new scenario preserves the old one |
| Period and precision documentation overstated behavior | Trading days were described as different-length months; all numeric outputs were described as strings; finite Decimal precision was called unrounded | Document fixed monthly horizons, integer counts, exact internal ratios, and 28-digit Decimal output conversion; include both trading-day counts in comparisons |
| Ignore rules missed common generated variants | Parallel coverage files, coverage XML, database journals, and logs could become Git candidates | Extend ignore patterns and verify representative paths, retaining `.env.example` |

These changes deliberately revise model semantics before any frontend exists. No stored record is automatically migrated or overwritten.

## Business and dimensional review

[Methodology](METHODOLOGY.md) now records formulas, units, cost classification, and edge semantics for every implemented metric. Revenue, product COGS, gross profit, delivery revenue, fulfilment, delivery, payment, acquisition, and shrinkage all scale with **fulfilled** orders. Monthly payroll and other fixed costs persist at zero demand. Total delivery cost is an informational subtotal, not an extra expense. Contribution excludes fixed labour; operating profit deducts it once.

Capacity is measured consistently in orders/day. Availability respects opening hours, productive fractions, service time, round-trip distance, and monthly paid-hour budgets. Stockouts precede capacity losses. Zero capacities, tied bottlenecks, exact capacity, zero demand, and staffing ceilings have explicit semantics. Break-even distinguishes mathematical thresholds from capacity feasibility; runway is a monthly operating-burn proxy with explicit null/no-burn behavior. Comparisons disclose trading days and undefined relative changes.

The [worked example](WORKED_EXAMPLE.md) independently establishes the income statement, capacity, break-even, and two stress cases. Its expectations are literal hand-calculated values rather than outputs generated by the engine.

## Test-quality assessment

- Existing hand-calculated statement tests were useful and retained. Conservation and same-scenario checks are supplemental invariants, not independent financial proof.
- API-to-engine equality checks establish transport/serialization consistency only. They cannot establish that the underlying financial formulas are correct; the separate worked examples do that arithmetic check.
- Replace break-even assertions that recomputed one returned field from another with independent expected values and profit signs immediately around the threshold. This also avoids enforcing equality between separately rounded recurring outputs.
- Remove four tests of the now-deleted caller-supplied volume parameter. Test the public safe entry point instead.
- The sole mocked database exception tests error redaction, not persistence. A real missing-table failure/recovery test, actual SQL rollback, file-backed round trips, and loopback HTTP across separate API processes provide independent persistence evidence.
- Rename the rollback test to describe what it actually checks: uncommitted flush rollback on session closure, not a failed commit.
- No test-count target or new coverage threshold was introduced. New tests address reproduced defects, previously missing boundaries, and real transport/persistence behavior.
